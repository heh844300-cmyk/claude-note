# 技術說明

## 架構

```
 手機 PWA ──Tailscale Serve (https)──┐
 公用電腦 ──Tailscale Funnel (https)─┤──► 127.0.0.1:8788 公開入口（QR 登入、公用電腦權限限制）──┐
 本機瀏覽器 ─────────────────────────┴──► 127.0.0.1:8787 ◄──────────────────────────────────────┘
                                            mobile/server.js（Node 20+，零依賴）
                                            ├─ 草稿工作佇列（整理／修改／更新，一次一件）
                                            ├─ Agent 工作佇列（研究、名詞拆分、灰色連結補寫一次一件；補寫實際用途同時最多 agentParallel 件）
                                            ├─ 英文閱讀佇列（找文章、準備單字與題目，一次一件）
                                            ├─ 排程（每 30 秒）：提醒推播、到期移到 .trash、灰色連結、例會報告、每日英文文章
                                            └─ 排程（每小時／每 6 小時）：重複名詞掃描、新版本檢查
                                                 │
                     ┌───────────────┬──────────┴──────────┬────────────────────┐
                     ▼               ▼                     ▼                    ▼
               AI（lib/ai.js）   網路（Agent）       Obsidian 筆記庫         Web Push
          Claude Code／Codex／   內建搜尋或          Claude-Notes/、研究/   （手機、電腦）
          OpenAI 相容 API        Tavily／Brave       .trash（到期、備份）
```

連接埠是預設值：`port` 預設 8787；公開入口 `publicPort` 預設關閉（0），由安裝精靈設定。

### 模組（`mobile/lib/`）

| 模組 | 負責 |
|---|---|
| `ai.js` | AI 介面：Claude Code CLI、Codex CLI 或 OpenAI 相容 API；角色有 organize（整理）、research（研究員）、librarian（圖書管理員）、plain（不用工具的單次問答） |
| `webtools.js` | openai 模式 Agent 的網路搜尋（Tavily／Brave）與安全網頁讀取 |
| `sandbox-mcp.js` | Agent 沙盒的 MCP 伺服器（`sandbox_run` 工具） |
| `vault.js` | 讀取整個筆記庫（排除點開頭的資料夾與 `vaultExclude`）：清單、搜尋、`[[名稱]]` 解析 |
| `related.js` | 找出和輸入相關的既有筆記（英文單字＋中文雙字詞、IDF 加權，筆記名稱出現在文中時大幅加分），附在 AI 提示裡 |
| `split.js` | 一次輸入拆成多篇、總覽、名詞解釋拆分 |
| `library.js` | 研究結果分篇（link／append／new／inline）、灰色連結、筆記庫掃描、名詞筆記補寫實際用途（`expandPrompt`／`appendExpansion`） |
| `agentq.js` | Agent 佇列挑下一件工作（補寫實際用途可同時多件，其他一次一件）、工作清單的上限 |
| `answers.js` | 使用者對「待釐清問題」的 💬 回答；已釐清的問題移到「已釐清」 |
| `refresh.js` | 「用最新規則更新」：只重寫正文區，打勾、回答、已釐清等使用者動過的內容由程式保留 |
| `dedup.js` | 重複名詞筆記與灰色連結的偵測、合併、改連結 |
| `tasks.js` | 解析與切換待辦（`📅` 到期日、`✅` 完成日） |
| `series.js` | 持續追蹤：主筆記設定、每日紀錄、「每日紀錄」索引、例會報告 |
| `htmltext.js` | HTML 教材轉文字：依 BOM、`<meta charset>` 判斷編碼（沒宣告時自動辨識 Big5），去掉 script／style／Word 標記，標題、清單、表格轉成 Markdown |
| `learn.js` | 學習：大綱解析、讀書計畫、出題解析、批改、錯題本與大綱筆記的產生、教材段落挑選、各種提示 |
| `reading.js` | 每日英文閱讀：分級測驗題目與評分、CEFR 等級升降、選主題、從網頁擷取文章、各種提示與容錯解析、筆記規則、在研究筆記追加「延伸閱讀與我的想法」 |
| `translate.js` | 線上翻譯：DeepL（預設）與 Azure Translator，單字、段落翻譯（分段、解析、錯誤訊息），只用內建的 `fetch`，沒有 SDK |
| `opencc.js` | 簡體轉台灣繁體（OpenCC 的 s2twp 流程，表檔在 `lib/opencc/`，Apache-2.0） |
| `mail.js` | 信件：解析 `.eml`（MIME、base64／quoted-printable、各種字元集含 Big5、RFC 2047 標頭）、去掉引用的舊信與簽名、讀行事曆邀請（`.ics`，含時區與夏令時間）、輸入消毒、整理用的素材與規則、限制 AI 的輸出。純函式 |
| `progress.js` | 英文閱讀的進步：週別運算、四個指標與和上週比較、停滯判斷、檢查點的時間與等級校正、每週主題的立場、週報的提示詞與解析 |
| `vocab.js` | 英文閱讀的詞彙：詞頻表（NGSL／NAWL）查詢、量測文章難度、從候選文章挑最接近等級的、讀者的單字紀錄（查過／學會）、理解題題型的選擇與計分 |
| `settings.js` | App 設定頁能改的設定清單、驗證、合併進 `config.json` |
| `rules.js` | 整理規則：`prompt.md` 後面接上 `prompt.local.md`（去掉 HTML 註解，空的就不接）；檔案不存在時建立只有說明註解的範本 |
| `version.js` | 讀 `VERSION`、`git fetch` 比對 GitHub 上的版本；解析 `CHANGELOG.md` 給「更新內容」視窗 |
| `auth.js` | 公開入口的 QR code 登入與裝置 session |
| `push.js` | Web Push（RFC 8291／8292，VAPID） |
| `qr.js` | QR code 產生器 |

### 一篇筆記的資料流

1. **新增**：`POST /api/drafts`（文字、照片、錄音）→ 草稿存在 `mobile/data/drafts/<id>/`
2. **整理**：`prompt.md` ＋ `prompt.local.md`（使用者自訂規則，`rules.js`）＋ 時間與提醒規則 ＋ 相關既有筆記（`related.js`）＋ 持續追蹤的主筆記（`series.js`）→ AI → 解析標頭（`TITLE`、`TAGS`、`EXPIRES`、`REMIND`、`AGENT`、`SERIES`）與正文
3. **確認**：使用者修改或請 AI 重改 → 上傳到 `Claude-Notes/YYYY-MM-DD 標題.md`（持續追蹤的話寫進當天的每日紀錄）
4. **上傳後的背景工作**：名詞解釋拆分 → 需要時 Agent 研究（研究員查資料 → 圖書管理員決定放哪裡 → 寫回「Agent 研究結果」、打勾、移到「已釐清」）
5. **排程**：提醒時間到推播；到期移到 `.trash`

### 筆記的區段

伺服器只改自己負責的區段，其他內容照原樣保留：

| 區段 | 誰寫 | 「用最新規則更新」時 |
|---|---|---|
| frontmatter、`# 標題`、`> 🧩`／`> 📌` 連回連結 | 上傳時 | 不動 |
| 正文（摘要、重點、思路、待辦、待釐清問題、已釐清、相關概念） | 整理 AI、使用者 | 重寫；打勾、📅、💬 回答、已釐清由程式補回 |
| `## 每日紀錄` | 持續追蹤 | 不動 |
| `## Agent 研究結果` | Agent | 不動（下次 Agent 執行時整段取代） |
| `## 附件照片`、`Original notes`、錄音逐字稿 | 上傳時 | 不動 |

| 檔案 | 用途 |
|---|---|
| `setup.cmd`／`setup/setup.ps1` | 安裝精靈，寫 `mobile/config.json` |
| `update.cmd` | `git pull` 後重新啟動。`prompt.md` 被改過時先另存成 `prompt.backup-<時間>.local.md` 再還原，否則 pull 會被擋下。cmd 執行批次檔時邊跑邊讀，pull 換掉檔案後會從同一個位元組位置接著讀新檔，所以：pull 到結尾整段包在一個 `( … )` 區塊裡（整塊先讀進記憶體，最後 `exit /b 0`，不會再讀到新檔）；前 4 行的長度要和 V23.1 以前的版本相同（118 bytes），舊腳本 pull 完才會剛好接到第 5 行 |
| `VERSION` | 版本號 `大版本.小版本`（右下角顯示、更新通知用） |
| `mobile/config.json` | 這台電腦的設定（不進版控） |
| `mobile/data/` | 草稿、推播金鑰與裝置、Agent 工作紀錄、登入 session、英文閱讀的文章與等級（`reading/`）（不進版控） |
| `mobile/logs/server.log` | 伺服器紀錄，出問題先看這裡 |
| `mobile/run-server.cmd`／`start-hidden.vbs`／`stop-server.cmd` | 啟動（當掉自動重啟）、無視窗啟動、停止 |
| `prompt.md` | 整理筆記的基本規則（進版控，更新時換成新版，使用者不要改） |
| `prompt.local.md` | 使用者自己的整理規則，接在基本規則後面，標成「使用者自訂規則」：衝突時以它為準，但輸出格式（`TITLE`、`TAGS` 等標頭）照原規則。不進版控（`*.local.md`），每次整理時重新讀取 |
| `claude-note.bat`／`.ps1` | 電腦版：整理剪貼簿文字（只支援 Claude Code） |

| `apiBaseUrl`、`apiKey` | OpenAI 相容服務的網址與金鑰 |

| `vision` | 整理用的模型能不能讀圖片 |

| `publicUrl` | 手機用的 Tailscale 網址（推播連結） |

| `audio`、`ffmpeg`、`whisper`、`whisperModel` | 錄音轉文字（進階，需自行安裝 ffmpeg 與 whisper.cpp） |

| `updateCheckHours` | 每幾小時到 GitHub 檢查新版本（預設 6，0 為關閉） |
| `readingReportTime` | 每週日幾點產生週報並推播（`HH:mm`，預設 `20:00`；空字串為不自動產生）。格式不對時當成空字串 |
| `readingCheckpoint`、`readingCheckpointDays` | 是否定期做檢查點文章（預設 `true`）、間隔天數（預設 28，可設 7～90） |
| `readingStances` | 每週一個主題讀三種立場（預設 `true`） |
| `readingNewsletters` | 英文電子報當每日文章（預設 `true`）：`mailScan` 把信頭有 `List-Unsubscribe`／`List-Id`／`Precedence: bulk` 且正文是夠長的英文（`reading.newsletterArticle`，≥250 字、英文字母 ≥85%）的信放進文章池 `data/newsletters.json`，不建草稿；關閉時電子報走一般信件筆記 |

| `mailEnabled`、`mailAccounts` | 讀取信件資料夾（預設 `true`）、信箱清單 `[{ name, folder, email? }]`（預設空，**只能改 `config.json`**，不在設定頁，路徑不是瀏覽器該設的東西；最多 5 個） |

| `mailEveryMinutes`、`mailMaxPerRun`、`mailNotify` | 檢查間隔（5～120 分鐘，預設 10）、每次最多整理幾封（1～20，預設 5）、新信推播（預設 `true`，只有封數） |

## AI 角色與安全設計

| 角色 | 能做的事 | 做不到的事 |
|---|---|---|
| 整理 | 讀草稿文字與照片 | 上網、讀其他檔案 |
| 研究員（Agent） | 網路搜尋、讀公開網頁 | 讀筆記庫、連到本機或內部網路 |
| 圖書管理員 | 看筆記庫（Claude：唯讀工具；其他 AI：伺服器挑出的相關筆記摘錄） | 上網；它只輸出「放哪裡」的決定，寫進檔案的文字都來自研究員 |

- openai 模式的網頁讀取（`fetch_url`）在這台電腦上執行，所以會拒絕所有本機、私有網段、Tailscale 位址，連線時與每次轉址都會重新檢查（`test/webtools.test.js`）
- Agent 的研究結果只會新增或追加到筆記，不會覆蓋既有內容；會改寫既有筆記的只有使用者確認過的動作（上傳更新草稿、合併重複名詞），而且舊版先備份或移到 `.trash`。伺服器不會寫到 `.obsidian`

## Codex（ChatGPT 訂閱）的權限鎖定

Codex 本身是會執行指令的 Agent，所以每次呼叫都會：

- `-s read-only`、`--ignore-user-config`（不載入使用者的 MCP 等設定）、`--ephemeral`
- 關閉 `shell_tool`、`unified_exec`、`view_image`、`apps`、`plugins`、`browser_use`、`browser_use_external`、`computer_use`、`in_app_browser`、`hooks`
- 在 `%TEMP%\claude-note-codex-empty` 執行：每次都清空，而且不在任何 git 專案裡，Codex 不會讀到專案的 AGENTS.md 或 .codex 設定；照片用 `--image` 直接附上
- 關閉的功能名稱如果在新版 Codex 不存在，Codex 會直接報錯停止（`Unknown feature flag`），不會在沒鎖定的狀態下執行
- 只有研究員加 `--search`（OpenAI 伺服器端的網路搜尋，連不到這台電腦）；管理員跟 OpenAI 模式一樣只拿到伺服器挑出的筆記摘錄

在 codex-cli 0.160.0 實測：要求它讀取工作資料夾外的檔案、執行指令、用 JavaScript（code mode）讀檔或連到本機的陷阱伺服器，全部失敗，陷阱伺服器沒有收到任何連線；網路搜尋正常。**Codex 大改版後請重新做一次這個測試**（`test/ai-codex.test.js` 只檢查參數，不檢查 Codex 本身的行為）。

## 一次輸入拆成多篇、名詞解釋拆分

- 整理時，AI 判斷輸入是否包含多個**彼此不相關**的主題（最多 `maxTopics` 個，預設 6）。是的話，原草稿變成「總覽」（保留照片、原始輸入、逐字稿），每個主題另開一份草稿，各自有提醒、到期、Agent。單一主題完全照舊；AI 輸出格式不對時，當成一篇處理；拆出的主題超過上限時，多的併進最後一篇（標題降一級），內容都不會遺失。學習功能的筆記一律整理成一篇，不會拆
- 總覽不能單獨上傳：等這一組的主題都上傳（或刪除）後自動寫入，連結用各篇實際的檔名，並在各篇開頭加上連回總覽的連結；主題全部刪除時總覽也跟著取消
- 修改單一主題時，會拿總覽裡的原始素材，只輸出那一篇
- 每篇筆記上傳後（總覽除外），背景工作找出「說明某個名詞是什麼」的段落：AI 只指出段落，必須逐字出現在筆記裡、不在「相關概念」裡，伺服器才把它換成「摘要（詳見 → [[研究/名詞]]）」；放哪裡由管理員判斷（新開、補充既有、或已涵蓋只放連結）。被換掉的原文保留在同一篇最後的「拆出前的原文」摺疊區塊。不看字數，由 AI 判斷是不是名詞解釋。關閉：`config.json` 的 `"termSplit": false`
- **補寫實際用途**：拆出來的名詞筆記只有原本那幾行定義。管理員決定「新開」的名詞，會再排一個 Agent 工作（`kind: 'expand'`）：`library.expandPrompt` 要它上網查證，寫「它是什麼、怎麼運作」（原本只有一兩句時）、「實際用途」（3～5 個具體情境、例子、不適合的時候、跟相近概念怎麼選）和「跟你筆記的關係」；`library.appendExpansion` 把它放在 `## 延伸說明` 底下，接在 `## 相關研究`／`## 來源` 之前，原本的內容不動。連結只能連到已經存在的筆記：提示詞附上 `研究/` 的名稱清單，要 AI 一字不差地用清單裡的名稱；寫入前 `library.unlinkUnknown` 再檢查一次，連不到任何筆記的 `[[…]]` 改成純文字（行內程式碼、程式碼區塊、`![[嵌入]]` 不動），避免多出沒有內容的灰色節點或同義詞節點（例如已經有「提示工程」，又多出 `[[Prompt Engineering]]`）。V24.2 補寫時沒有這道檢查，V24.3 啟動時會自動清一次（`repairExpansionLinks`：只動 `## 延伸說明` 區塊，做完在資料夾寫 `expand-links-repaired`，之後不再執行）。輸出沒有「實際用途」就當失敗，不寫入；寫入前重新讀取，已經補過（`library.needsExpansion`）就跳過；摘要寫「與 [[X]] 是同一個概念」的指向筆記也不補，完整說明在 X。需要 Agent 搜尋（`agentAvailable()`），關閉：`"expandTerms": false`。自動補寫失敗不推播
- **舊筆記補寫**：`GET /api/expand` 列出還沒有實際用途的 Agent 研究筆記（`generated_by: claude-agent`，沒有 `## 延伸說明` 也沒有「實際用途」小節）；`POST /api/expand {"all":true}` 全部排進 Agent 佇列，`{"name":"名詞"}` 只補一篇（完成時推播）。App 的「📒 筆記」→「🔎 研究」有「💡 補寫實際用途」方塊：還有沒補的筆記、而且 Agent 能搜尋時才顯示，按下去送 `{"all":true}`，補寫中顯示還剩幾篇（`GET` 回傳的 `pending`）

## Agent 沙盒

安裝精靈第 7 步（`setup/sandbox-setup.js`）建立一個隔離的 WSL 發行版（Ubuntu 24.04）：

- 用沒有管理員權限的 `agent` 使用者（uid 2001）執行；`sudo`／`su` 不能用、看不到 Windows 磁碟、不能執行 Windows 程式
- 防火牆只允許連公開網路：本機、WSL 閘道、區網、Tailscale 都擋（`sandbox/ensure-sandbox.sh`，每個指令前都會重新套用）
- 建立完會跑 `sandbox/isolation-test.sh`（用這台電腦實際的 Tailscale 位址與區網閘道），**有任何一項沒擋住就不啟用**；`/mnt/wsl` 可寫入是已知限制（整個 WSL 共用，遮掉會讓 WSL 壞掉）
- 每個 Agent 工作第一次用沙盒時，從 `clean.tar` 快照還原成乾淨狀態
- 只會 `--terminate` 沙盒自己，絕不 `wsl --shutdown`；WSL 已有同名、但不是這個程式建立的發行版時，會停止而不動它
- Claude Code 透過 `--mcp-config` 使用；Codex 透過 `-c mcp_servers.sandbox...`，**只預先核准 `sandbox_run` 這一個工具**（codex-cli 0.160.0 實測可用；如果之後的版本不認這個設定，呼叫會被拒絕，不會變成沒有限制）
- 實測（codex-cli 0.160.0）：讓 Codex 用沙盒連本機、閘道、區網 IP、Tailscale IP、讀 C 槽、提權，全部失敗，架在這台電腦所有網路介面上的陷阱伺服器沒有收到任何連線；實際安裝並執行 cowsay 成功
- 解除安裝精靈會先移除本程式建立的沙盒，才刪除程式資料夾

## 研究結果分篇

- `link`：已有筆記涵蓋 → 原筆記只放摘要＋連結
- `append`：既有筆記的細節 → 補在那篇最後（標示「🔎 Agent 補充」，原文不動）
- `new`：獨立概念 → `Claude-Notes/研究/` 開新筆記；名稱優先用現有的灰色連結
- `inline`：留在原筆記
- 重跑同一篇不會重複補充；有到期日的筆記不會被補充（改開新筆記）

## 灰色連結自動補

伺服器每 30 秒掃描筆記庫：內容空白、檔名跟某篇筆記的 `[[連結]]` 相同、而且空白超過 1 分鐘的筆記，會交給 Agent 寫成完整筆記，移到 `Claude-Notes/研究/`。內容分「通用說明」「實際用途」（具體情境、例子、跟相近概念怎麼選）和「跟你筆記的關係」。1 分鐘內打字就不會被碰。手動指定：`POST /api/fill {"name":"名詞"}`。

## 參考既有筆記

整理、修改、更新、Agent 研究、灰色連結補寫之前，`related.js` 會從筆記庫挑出最相關的幾篇（摘要＋章節＋開頭，每篇約 1000 字），連同 `研究/` 裡已有的名詞清單附在提示裡。

- 只透過 `vault.js` 讀取，所以 `vaultExclude` 和點開頭的資料夾不會送給 AI
- 持續追蹤的每日紀錄不列入（幾十篇相似的進度會擠掉其他筆記），它們由持續追蹤另外提供
- 使用者在 💬 回答裡寫的 `[[筆記]]`，內容會整篇附給 Agent（Agent 本身讀不到筆記庫）

## 回答待釐清問題、已釐清

- 回答寫成問題底下的 `  - 💬 我的回答：…` 子項目；儲存時比對行號與原文，筆記剛被改過就拒絕（避免寫錯行）
- Agent 輸出 `RESOLVED: <問題原文> | <結論>`：使用者回答過、或查到明確事實的問題，從「待釐清問題」移到 `## 已釐清`（問題、回答、結論）；要使用者拍板的問題不算

## 用最新規則更新

- 一篇或全部筆記先產生「更新草稿」，確認後才上傳；一律用 `bigModel`
- 上傳時只取代正文區（見[筆記的區段](#筆記的區段)），舊版先備份到 `.trash/<名稱> (更新前 <時間>).md`
- 草稿建立後筆記被改過（忽略打勾與回答）就拒絕上傳；之後的打勾、回答在上傳時合併
- 不更新：`研究/` 名詞筆記、總覽、使用者自己寫的筆記、每日紀錄

## 清除重複名詞

- 掃描範圍：`研究/` 筆記（名稱＋摘要）和可見筆記裡的灰色連結；系統先用名稱比對（去掉「方法、框架、模型…」等字尾）當提示，再由 AI 判斷是不是**同一個概念**（一部分、一種技巧、相關但不同都不算）
- 每一組都要使用者按「合併」才動：重複筆記的內容併進保留的那篇、加進 `aliases:`、全筆記庫的 `[[重複]]` 改成 `[[保留|原本顯示的字]]`、重複的那篇移到 `.trash`
- 按「不是重複」的組合之後不會再出現；灰色連結補寫時，AI 判斷是同一個概念的話直接改連過去，不建新筆記

## 待辦

- 掃描整個可見筆記庫的 `- [ ]`／`- [x]`；`📅 YYYY-MM-DD` 是到期日、`✅ YYYY-MM-DD` 是完成日（和 Obsidian Tasks 外掛相同格式）
- 打勾時比對行號與原文，保留檔案原本的 BOM 與換行

## 持續追蹤

主筆記的 frontmatter（都是單一值，簡單的 YAML 解析器就讀得到）：

```yaml
series: true
series_name: "例會進度"   # 每日紀錄的檔名：YYYY-MM-DD 例會進度.md
series_days: "1-5"        # 週一 = 1 … 週日 = 7，也可以寫 "1,3,5"
series_time: "12:10"      # 留空 = 不自動整理報告
series_start: 2026-11-16  # 這天之前不整理報告
```

- **整理**：使用者選「接續到」，或交給 AI 判斷（提示裡附上最多 4 篇主筆記，每篇含最近兩次紀錄），AI 在標頭輸出 `SERIES: <主筆記標題>` 或 `SERIES: none`
- **每日紀錄**：frontmatter 有 `series_of: "<主筆記檔名>"`，開頭 `> 📌 接續 [[主筆記]]`；不會到期、沒有自己的提醒；日期取「寫下的那天」；同一天第二次上傳接在後面的 `## 補充（HH:mm）`
- **索引**：主筆記的 `## 每日紀錄`，最新的在最上面（在正文區之外，更新、名詞拆分、Agent 都不會動它）
- **報告**：例會前 30 分鐘（`series_lead`）由排程觸發，不走 Agent 佇列；取上一次例會日之後的紀錄，用 `smallModel` 寫成 `## 例會報告`，放在當天紀錄最上面並推播。同一場例會只觸發一次（記在 `data/reminders-sent.json`，重開機也不會重複）；AI 失敗時改放直接從筆記整理的紀錄與未完成待辦

## 學習

每個主題一個資料夾 `Claude-Notes/學習/<主題>/`：

| 檔案 | 內容 |
|---|---|
| `.learn/topic.json` | 主題的真實資料：章節與進度、教材清單、測驗紀錄、錯題、考試日期、推播時間（點開頭的資料夾 Obsidian 不顯示） |
| `.learn/lesson-<章>.json` | 該章的教學內容、追問紀錄、上課筆記（一個字串；用了康乃爾筆記法的線索或總結時分成三段，見「懸浮筆記」） |
| `.learn/quiz-<id>.json` | 題目、**答案與評分要點**、作答、批改結果 |
| `.learn/text/<教材>.txt` | 照片、HTML 教材轉出來的文字（只轉一次） |
| `.learn/outline-review.json` | 大綱建議（AI 依教材提出的調整，等使用者套用或忽略） |
| `大綱.md`、`錯題本.md` | 由 `topic.json` 產生，每次變動都重寫（不要手動改） |
| `<章節標題>.md`、`測驗 ….md` | 使用者的筆記，經過一般的「整理 → 草稿 → 上傳」流程；同名時接在後面。檔名和內容都不寫「第幾章」（`learn.noteTitle`，整理規則也要求 AI 用主題名稱稱呼）；同一章已經有連結的筆記（`topic.json` 的 `note`，使用者改過檔名也一樣）時接在那篇後面，之後跨章節回頭看比較方便；大綱裡的章節順序照舊 |
| `教材/` | 原始教材 |

- **AI 呼叫**有自己的佇列（不排在 Agent 後面），一次一件；前端輪詢狀態。伺服器重新啟動時，做到一半的工作標成失敗讓使用者重來
- **章節代號**：每章的 `n` 是永久代號，上課檔（`lesson-<n>.json`）、`levels`、題目與錯題的 `chapter`、學習筆記草稿都用它對應；畫面和筆記上的「第 N 章」是章節在陣列裡的位置（`learn.posOf`）。新章節的代號由 `outline.idAllocator` 發：取章節、`levels`、錯題、`lesson-*.json` 檔名裡用過的最大值再往上（存在 `topic.nextChapter`），被合併掉的代號、留下孤兒上課檔的代號都不會再發出去。給 AI 的章節清單寫成 `[代號 7] 第3章「標題」`，出題要它在 `chapter` 填代號；不在範圍內的代號改成 null
- **大綱**：有教材時，文字與照片轉出的文字用 `pickPassages`（和 `related.js` 一樣的雙字詞比對）挑出最多 2 萬字，PDF 交給 Claude 用 Read 工具整份讀；沒有教材時用研究員角色上網查證（沒有搜尋服務就只用 AI 知識）
- **第一份大綱之後**：`POST …/outline` 只在還沒有章節時能用（之後回 409），避免整份重排打亂代號。大綱改用「建議」調整（`lib/outline.js`）：
  - **什麼時候檢查**：上傳教材後自動排一次（排在照片轉文字後面，同一個佇列一次一件），只對照還沒看過的教材（`topic.outlineMaterials`；舊主題沒有這個清單時，以 `outline.at` 之後加入的教材為新教材）；按「依教材檢查大綱」（`POST …/outline/check`）對照全部教材
  - **AI 的輸出**：每條一段 `=== CHANGE ===`，`TYPE` 是 `ADD`（新增章節，`CHAPTER` 寫接在哪一章後面，0 是最前面）、`POINTS`（補重點）、`EDIT`（改標題或重點）、`MOVE`（`AFTER`）、`MERGE`（`INTO`）、`CONFLICT`（`OLD`／`NEW`：教材和既有說法不同，AI 不判斷誰對），最多 12 條；`NONE` 表示不用改
  - **已上過的章節**（`outline.lockedIds`）：打勾完成、有上課檔（任何狀態）、有連結的筆記、有難度等級、有錯題指向它。只能 `POINTS`／`CONFLICT`，`EDIT`／`MOVE`／被 `MERGE` 掉的建議標成 🔒 不能套用。**套用時在 `updateTopic` 鎖裡用當下的狀態重新檢查**，審查後才開始上的章節一樣擋下
  - **套用**（`outline.applySuggestions`，`POST …/outline/apply`，`{ ids, action: apply | ignore | reopen }`）：照順序一條一條套用，套不上的（章節已不在、同名、重點已經有了）回報原因。已上過的章節多出來的重點記在 `c.fresh`（🆕）；`CONFLICT` 套用時把「新教材的說法：…（原本：…）」加成一個重點，已上過的章節同樣標 🆕
  - **存放**：建議存在 `.learn/outline-review.json`（不寫進 `topic.json`），每次檢查有 run id，較新的檢查會讓舊的結果直接丟掉；主題已刪除就不寫回。新的檢查保留之前還沒處理的建議、新的接在後面，已套用或忽略的不再帶著。伺服器重新啟動時，中斷的檢查標成失敗
  - **調整紀錄**：`topic.outlineLog`（時間、依據的教材、這次改了什麼，最多 50 筆），大綱.md 最後列出最近 20 筆
  - **補課**（`POST …/lesson/:n/supplement`）：只針對 `c.fresh` 的重點寫一段補充教學，附上原本的教學內容並要求不要重講，說法不同的要說明差異；接在教學內容最後面（`## 🆕 補充：新教材的內容（日期）`），完成後清掉這些 🆕。狀態存在上課檔的 `supp`，失敗不影響原本的教學內容；整章重新準備時也會清掉 🆕。還沒上過課的章節不用補課，上課時就會包含新的重點
  - **補課進筆記**：這一章已經有連結的筆記（`c.note`，檔案還在）時，補課完成後自動建立一份學習筆記草稿（`learnDraft`，`learn.supplement: true`），標題用那篇筆記的名稱，素材只有新的重點和補充教學（`learn.supplementMaterial`），整理規則多一條「只整理補充、不要重寫原本的內容」（`LEARN_RULES` 的 `supplement`）。草稿一樣經過上傳前審查，上傳時照同名規則用日期分段接在那篇筆記後面。上課檔的 `supp.draft`／`supp.note` 記住這份草稿，`GET …/lesson/:n` 的 `suppDraft` 表示草稿還在等確認。還沒有筆記的章節不建草稿：之後「完成這章並整理筆記」時，`notesMaterial` 會保留教學內容最後的補充段落（以 `learn.SUPP_MARK` 分段；本文最多 6000 字、每段補充最多 3000 字），不會因為截斷而漏掉
- **上課**：研究員角色（AI 知識＋網路查證）＋相關既有筆記；追問用不帶工具的單次問答，附上這一章的內容和最近 6 則問答
- **出題**：輸出 JSON（每題一個物件，壞掉的部分略過）；範圍內章節的教材段落、考古題段落（仿照風格）、待複習錯題（只練錯題）附在提示裡。**答案、評分要點、解析只存在伺服器**，交卷前送到瀏覽器的只有題目和選項
- **使用者的要求**：主題的 `rules`（教學要求）放進大綱、上課、追問、出題、批改的提示；每份測驗的 `settings.rules`（出題要求）放進出題與批改的提示，最後一次用的會存成 `quizRules` 下次預先帶入。要求放在輸出格式之前，並註明「和格式衝突時以格式為準」
- **動態難度**：等級與計數器由程式保存，AI 只負責判斷對錯、照指定等級出題。規則（`learn.stepLevel`）：連對 2 題升一級、連錯 2 題降一級（1～5 級，起始 2 級）、答錯第 1 次維持等級並要求再試、用了提示才答對只清掉連錯不算連對。每章等級存在 `topic.json` 的 `levels`，每份測驗批改後依作答順序更新；應考出題選「自動」或章節小測驗時，提示裡寫出每章的等級與該級的出題標準。小問題的狀態存在 `lesson-<章>.json` 的 `adapt`（從該章等級開始）：提示裡直接給 AI「答對時／答錯時」該怎麼做的分支（不用 AI 自己算），AI 回答的第一行寫 `JUDGE: correct|wrong|none`，伺服器讀出後藏起來並更新等級
- **5 級難度**（`learn.LEVELS`，每級分別寫了上課小問題 `chat` 與測驗出題 `quiz` 的標準；舊資料的 easy／medium／hard 對應到 2／3／4 級）：

  | 等級 | 名稱 | 測驗出題標準（摘要） |
  |---|---|---|
  | 1 | 基礎建立 | 最基本的定義與觀念辨認；選擇題可以只有兩個合理選項（沒有是非題型，用二選一代替） |
  | 2 | 標準入門 | 基礎專有名詞與定義、單一概念 |
  | 3 | 概念應用 | 情境應用、小型計算或推演 |
  | 4 | 進階變形 | 邊界條件、常見陷阱、多概念綜合、找錯題 |
  | 5 | 大師挑戰 | 底層原理、方案取捨、設計與優化 |

  出題設定的 `difficulty` 是 `auto` 或 `1`～`5`；章節小測驗固定用 `auto`。這個版本之前做過的測驗不回溯計算，章節沒有紀錄時從 2 級開始
- **HTML 教材**（`htmltext.js`）：上傳時轉成文字存到 `.learn/text/`，之後和文字檔一樣用 `pickPassages` 挑段落；轉出來幾乎沒有文字的（例如整頁都是圖片）直接拒絕
- **作答提示**：每題最多 2 個，交給 AI 時附上答案（只給 AI 參考）並要求不能說出、描述或用排除法暗示答案；回來的提示若包含正確選項的文字或字母、或任一可接受的填空答案，就重新產生（最多 2 次），仍不行就改用章節重點當提示。提示存在測驗檔裡，結果畫面標出用了幾個
- **追問的小問題**：學生問新問題時，回答最後出一個「🤔 小問題」；學生在發問框回答時，AI 先指出哪裡對、哪裡是盲點再補充，**不再接著出新的小問題**（避免一直追問下去）。唯一的例外是第 1 次答錯：請學生「🤔 再試一次」同一題；同一題第 2 次答錯就直接說明答案。想多練時按「🎯 再來一題」（`POST …/lesson/:n/ask` 帶 `{ more: true }`）：只照目前等級出一個新的小問題，不判斷對錯、不改連對連錯的計數
- **發問與回答共用一個輸入框**：送出時帶 `mode`：`ask`（新問題，一定不判斷對錯）、`answer`（回答目前等著的小問題，一定判斷對錯；提示裡附上那一題）、`auto`（預設，AI 自己判斷，提示裡也附上等著的小問題）。等著的小問題由 `learn.pendingQuestion` 從最後一則回答的「🤔 小問題／再試一次」取出；沒有的話不能選「回答小問題」（伺服器也會拒絕）
- **問答串**：每則紀錄存 `kind`（`ask`／`answer`／`more`），`learn.threadsOf` 把新問題當成一串的開頭，小問題的回答和「再來一題」接在它底下（舊紀錄沒有 `kind`：有判斷對錯的、或「再來一題」算回覆）。`GET …/lesson/:n` 回傳 `threads` 和 `pending`。上課頁每一串是一個 `<details>`，標題列出回覆數和 ✅❌；最新的一串預設展開、舊的收起，使用者手動切換的狀態記在記憶體裡，畫面輪詢重畫時保留
- **懸浮筆記**（`app.js` 的 `fn*`、`public/cornell.js`）：上課頁和測驗頁共用一個固定在畫面上的筆記視窗，`fnBind(ctx, text)` 在進入某一章／某份測驗時把它接到對應的 `PUT …/notes`，`fnSync()` 在切換分頁或頁面時決定要不要顯示（離開時先存檔）。
  - **版面**：寬度不到 700px 是底部抽屜，拖標題列改高度，用 `visualViewport` 算出鍵盤高度後貼在鍵盤上方（鍵盤出現時最高占可見範圍的 62%），並把 `main` 的下方留白加大，頁尾的內容仍然捲得到；700px 以上是 `position: fixed` 的面板，拖標題列移動、右下角調整大小（CSS `resize`），不會被拖出畫面。面板夠大（寬 560、高 300 以上）時三個部分同時顯示，否則用分頁。
  - **儲存**：伺服器端仍然是一個字串（`lesson.notes`／`quiz.notes`），API 和資料格式沒有改。上課筆記用 `Cornell.serialize` 寫成 `## 🔑 線索`／`## ✏️ 筆記`／`## 📝 總結` 三段；只寫了「筆記」時存成原本的純文字，舊筆記用 `Cornell.parse` 讀進來全部算「筆記」。測驗筆記不分段。打字 1.5 秒後自動存，收起視窗、離開頁面、切到背景時立刻存；存檔排成一條鏈（`fn.saving`），舊的內容不會蓋掉新的，重新進入同一章前先等它存完。
  - **選取引用**：在 `#llBody`、`#llChat`、已批改的 `#lqForm` 選取文字會出現兩個按鈕，「📌 記到筆記」用 `Cornell.quote` 加成引用（最多 600 字），「🔑 加到線索」用 `Cornell.cue` 加成一行（最多 120 字）；不會自動打開視窗或叫出鍵盤。
  - **偏好**：位置、大小、抽屜高度、電腦上是否打開存在 `localStorage`（`fn-pos`、`fn-size`、`fn-sheet`、`fn-open`）。
  - **整理**：`LEARN_RULES` 多一條規則：筆記裡有「線索」「總結」小標題時，線索原樣列成「## 複習線索」（不回答、不增刪、不寫成待辦），總結放進摘要
- **批改**：選擇題比對選項；填空每個空格可接受多種寫法（忽略全半形、大小寫、空白與標點），依答對的空格給分；開放題所有題目一次交給 AI，分數限制在 0～滿分，沒作答直接 0 分。低於滿分六成記進錯題本；「只練錯題」的題目帶著錯題編號，答對就把那題移到「已熟練」
- **讀書計畫**：從今天到考試前一天，最後約 20%（最多 3 天）留給模擬考與錯題，未完成的章節平均分到其他天、前面的天先排；每次都從「還沒完成的章節」重算，所以落後會自動往後排。每天 `planTime` 後 3 小時內推播一次（記在 `data/reminders-sent.json`）
- **PDF**：只有 provider 為 `claude` 時可以上傳。實測 Claude Code 的 Read 工具不指定頁數時可以整份讀（含掃描檔）；指定頁數需要另外安裝 poppler，所以不使用
- **上傳前審查**：學習筆記的草稿整理好（或請 AI 修改完）後，自動跑一次審查（`learn.reviewPrompt`）：對照草稿的原始內容（這一章的教學內容、上課問答、測驗結果、使用者筆記）、`pickPassages` 挑出的教材段落，有搜尋服務時用研究員角色上網查證，沒有就用不帶工具的單次問答。PDF 教材不會列入審查（畫面會註明）。AI 只挑事實與觀念錯誤（不挑文筆、格式、心得），最多 10 條，每條 `LEVEL`（錯誤／不精確／待查）、`QUOTE`（逐字原文）、`PROBLEM`、`FIX`（可以直接取代原文的寫法）、`SOURCE`。`learn.parseReview` 在正文裡找原文（忽略多餘空白），找不到的只顯示、不能自動套用；`learn.applyFixes` 每條只取代一次
  - 結果存在草稿資料夾的 `review.json`（不寫進 `draft.json`，避免和使用者存檔互相覆蓋），有自己的佇列（不卡上課，也不排在 Agent 後面）。每次審查有自己的 id：重新審查或請 AI 修改後開始的新審查，會讓還在跑的舊審查結果直接丟掉；草稿已經上傳或刪除時也不寫回（不會留下空的草稿資料夾）。伺服器重新啟動時，中斷的審查標成失敗
  - `POST /api/drafts/:id/review`（重新審查，可附目前的編輯內容）、`POST /api/drafts/:id/review/apply`（`{ ids, action: apply | ignore | reopen }`，附目前的編輯內容，套用後回傳新的草稿）。公用電腦也可以用。草稿清單顯示「🔍 審查中」「⚠️ N 個問題」「✅ 已審查」；N 只算還沒處理、原文還在正文裡的「錯誤」和「不精確」，上傳前的確認視窗也用同一個數字提醒
- 系統產生的檔案不用 `- [ ]` 和 `📅`，避免出現在「待辦」分頁和 Tasks 外掛

## 每日英文閱讀

每天一篇跟使用者最近的筆記有關、符合 CEFR 等級的真實英文文章。邏輯在 `lib/reading.js`，`server.js` 負責佇列、排程和檔案。

**存放**（都在 `mobile/data/reading/`，不在筆記庫裡）：

| 檔案 | 內容 |
|---|---|
| `state.json` | 等級（`level`，沒有就是還沒做分級測驗）、連續偏易／偏難的次數（`up`／`down`）、釘選的主題（`pinned`） |
| `<日期>-<亂數>.json` | 一篇文章：主題、網址、段落（`paras`，`## ` 開頭是小標、`- ` 開頭是清單）、文章難度、簡化版、單字表、題目與**答案**、對照筆記的提問、作答結果、使用者的想法、草稿與筆記的對應 |

讀取和寫入都走同一個鎖（`updateArticle`、`updateReadState`）。

- **分級測驗**：`reading.PLACEMENT` 是寫在程式裡的 12 題（A2、B1、B2、C1 各 3 題），由程式評分，不呼叫 AI：從 B1 往上，每一級 3 題答對 2 題算通過，遇到第一個沒通過的等級就停（上面的等級就算答對也不算），都沒通過是 A2。沒選的題目不算答對。答案不會送到瀏覽器（`placementView`）。重新測驗或手動改等級時，連續次數歸零
- **選主題**（`reading.pickTopics`）：最近 7 天修改過的筆記名稱（`Claude-Notes/` 底下，不含 `學習/` 和 `英文閱讀/`；一篇都沒有時用最新的 5 篇，去掉檔名開頭的日期），每兩篇穿插一個釘選的主題；最近 10 篇文章用過的主題跳過，全部用過時從最久以前用的開始。挑出 3 個交給 AI，要它優先用第 1 個；主題來自筆記時附上那篇筆記的一句摘要（`topicHints`），讓 AI 知道它指的是哪個領域，不會只看名稱找文章。閱讀筆記的代號是 `英文閱讀/<檔名>.md`（`safeNote`），名詞拆分、在 App 開啟筆記都用它
- **找文章**（英文閱讀自己的佇列，一次一件，不排在 Agent 或上課後面）：
  1. 研究員角色（`ai.research`，會上網）依 `reading.findPrompt` 找 2～3 篇候選：免費、沒有付費牆、500～1500 字、難度接近使用者的等級、不是讀過的網址（附上歷史文章的網址）。輸出 `TOPIC:` 和幾段 `=== CANDIDATE ===`（`URL`／`TITLE`／`SITE`／`WHY`），`parseCandidates` 只留下 http(s)、不是 PDF、沒讀過的
  2. **正文由伺服器自己讀**，不經過 AI，所以一定是網頁上的原文：`webtools.fetchUrl`（`keepHtml`；一樣擋本機、私有網段、Tailscale 位址）→ `reading.extractArticle` 取最大的 `<article>`（沒有就用 `<main>` 或整頁），去掉導覽、頁尾、表單、程式碼區塊、圖說，留下段落、小標和清單。英文字母不到六成（不是英文）或不到 250 個字的候選就換下一篇；都不行就失敗。超過約 1300 字時在段落邊界截斷（`trimArticle`），畫面註明只有前半
  3. 不帶工具的單次問答（`bigModel`，`reading.prepPrompt`）一次寫出：文章難度 `LEVEL`、單字表 `GLOSS`、3 題理解選擇題 `QUESTIONS`（JSON）、對照使用者筆記的提問 `REFLECT`、難度高於使用者等級時的簡化版 `SIMPLIFIED`。提示裡附上 `related.find` 挑出的最多 4 篇相關筆記（不含之前的閱讀筆記）
  4. `reading.parsePrep` 容錯解析：單字表只留文章裡真的有的字；格式不對的題目丟掉；`REFLECT` 的 `NOTE` 必須是附上的筆記名稱，否則當成沒有對照的筆記；任何一段壞掉都只是少了那一段，文章照樣可以讀。**要不要簡化版由程式決定**：文章難度高於使用者等級才留下，AI 沒寫的話再單獨要一次（`simplifyPrompt`）
- **排程**（`readingTick`，跟其他排程一樣每 30 秒）：已經做過分級測驗、Agent 能搜尋、過了 `readingTime`、今天還沒有文章時準備一篇，完成後推播（連結 `/?read=<id>`）。每天只觸發一次（記在 `data/reminders-sent.json` 的 `reading|<日期>`）；電腦當時關機的話，當天開機後補做；失敗時推播一次請使用者自己再按。手動按「現在找一篇文章」不推播。同時只會有一篇在準備中
- **點單字**（`POST /api/reading/:id/gloss`）：單字表裡有的直接回傳；沒有的用 `smallModel` 做一次不帶工具的問答，只給那個字所在的句子（`reading.sentenceOf`），結果記進那篇文章的單字表，同一個字不會問第二次
- **太難了**（`POST …/simplify`）：記下 `tooHard`，沒有簡化版時在背景產生（狀態存在 `simp`，有自己的 id，舊的結果不會蓋掉新的）
- **讀完**（`POST …/finish`，`{ answers, thought, simplified }`）：程式對答案（`reading.grade`），之後 `GET` 才會帶答案和說明。等級由程式調整（`reading.outcomeOf`／`stepLevel`）：全對而且讀的是原文算「偏易」，按過「太難了」或答對不到一半算「偏難」，其他算「剛好」並把連續次數歸零；連續 2 篇偏易升一級、連續 2 篇偏難降一級，範圍 A2～C1
- **筆記**：讀完時建立一份草稿（`source: reading`，`draft.reading` 記住文章），走一般的草稿佇列和「確認 → 上傳」。整理規則多一段 `reading.READ_RULES`：區段只有摘要、重點整理、我的想法、相關概念；「我的想法」只能整理使用者自己寫的字句，沒寫就省略；不整段翻譯、不抄原文。草稿被刪掉時，文章頁可以再建一次（`POST …/note`）
- **上傳**（`uploadReadingNote`）：寫進 `Claude-Notes/英文閱讀/<閱讀日期> <標題>.md`（同名加 `(2)`），frontmatter 有 `source: "reading"`、`reading_url`、`reading_level`；標題下面一行放原網站和 App 閱讀頁（`publicUrl/?read=<id>`，沒有設定 `publicUrl` 時用本機網址）的連結。**不附「Original notes」**，英文原文不會進筆記庫。接著：
  - 筆記正文連到的研究筆記（`reading.linkedNames`，加上提問對照的那一篇，只算 `研究/` 裡真的存在的，最多 5 篇），在最後的 `## 延伸閱讀與我的想法` 加一行 `- 日期 [[英文閱讀/…|標題]]`（`reading.appendFurther`：只追加、保留 BOM 與換行、同一篇文章不會加第二次）。使用者的想法取自**確認後的草稿**的「我的想法」區段，以 `：💬 …` 接在提問對照的那一篇（那篇不是研究筆記時放在第一篇）
  - `termSplit` 開著時，照一般筆記排名詞拆分，還沒有筆記的名詞由圖書管理員決定新開或補充
- **點單字（線上）**：有金鑰且 `translateWords` 開著時，`glossWord` 呼叫所選服務。DeepL 只有一般翻譯（`/v2/translate`，`source_lang=EN`、`target_lang=ZH`），譯義只有一個、沒有詞性。Azure 呼叫 `dictionary/lookup`（`from=en&to=zh-Hant`，只送單字本身），回傳的譯義依 `confidence` 排序，`translate.formatSenses` 整理成一行（例如 `n. 敘述、故事　a. 敘述的`，最多三個詞性、每個三個譯義）。查不到就回傳空字串，**不存進單字表**，畫面顯示「字典查不到這個字」。沒有金鑰或關閉時，才走原本的小模型解釋句中的意思
  - 不用 `includeAlignment`：Azure 文件標示它是實驗性功能，有使用限制，而且繁體中文是否支援沒有確認
- **台灣繁體**：DeepL 只會輸出簡體，所以它的結果經過 `opencc.js`：先 STPhrases／STCharacters 轉繁體，再用 TWPhrases（例如 數據→資料、軟件→軟體）和 TWVariants（僞→偽）轉成台灣用語。Azure 直接輸出繁體，不經過轉換
- **段落翻譯**（`POST /api/reading/:id/para`，`{ para, simplified }`）：只翻那一段，`to=zh-Hant`，結果存在文章的 `zh.o`（原文）或 `zh.s`（簡化版）裡，之後打開不會再送。文章沒準備好、沒有金鑰、或設定關閉時回 409 並說明原因
- **備援**：線上翻譯失敗（金鑰錯、額度用完、逾時、連不上），或字典回傳空白，就改用小模型（`smallModel`）：單字用原本的 `glossPrompt`，段落用 `paraTranslatePrompt`（要求台灣繁體）。小模型的結果也存進文章（單字存在 `gloss`，段落存在 `zh`），下次不再送出。回應的 `via` 標示來源：`online`、`ai` 或 `saved`。簡轉繁的表格沒有載入時，DeepL 的結果會直接報錯，不會以簡體顯示，同樣改用小模型
- **翻譯請求**（`lib/translate.js`）：每次最多 25 段、4 萬字元（Azure 單次上限 5 萬字元）；單段超過 4 萬字元直接拒絕，不會切斷。401（金鑰或區域不對）、403（額度用完或沒權限）、429（太頻繁）、400 和逾時都轉成繁體中文的說明。金鑰不會出現在任何 API 回應或設定頁裡
- **量測難度**（`lib/vocab.js`、`lib/wordlists/`）：詞頻表是 NGSL 1.2（2809 字，行的順序就是詞頻排名，分成前 1000、1001～2000、其餘三個頻段）、NGSL 補充字和 NAWL 1.2（學術用字），CC BY-SA 4.0，出處寫在每個檔案開頭和 `lib/wordlists/README.md`。`vocab.difficulty` 的分數 ＝ 不在最常用 1000 字裡的字的比例 ＋ 平均句長 ÷ 100，用兩個分界點分成三級，對應 B1／B2／C1（這個對應是假設）。句子中間大寫開頭、又不在詞表裡的字當成專有名詞，不算生字
  - **驗證**（OneStopEnglish 語料，189 篇文章各有初、中、高三個版本；沒有放進專案）：同一篇的三個版本排出正確順序 92.6%（只用詞頻 75.1%）；分界點用一半文章決定，在另一半上三級完全判對 59.9%、差一級以內 95%。所以它只用來**比較候選文章**和當作 AI 判斷之外的第二個依據，文章顯示的難度仍然是 AI 的 `LEVEL`，量測的等級另外存在 `lex.level`
  - **用在哪裡**：候選文章改成全部抓回來量，`vocab.pickByLevel` 選最接近使用者等級的（一樣近時，難一級優先於易一級，再來照 AI 的排序）；AI 判斷的等級**或**量測的等級高於使用者，就準備簡化版
- **單字紀錄**（`data/reading/vocab.json`，`vocab.recordArticle`）：每個原形一筆 `{ seen, taps, since }`。點單字時（包含單字表裡本來就有的字）把那個字記在文章的 `taps`；讀完時才更新紀錄：點過的字 `taps` 加 1、`since` 歸零；之前點過、這次出現但沒點的字 `since` 加 1，到 3 就算學會（`graduated`，畫面會列出來）；沒點過的字只記 `seen`（最常用 1000 字不記）。判斷「認不認識」（`vocab.isKnown`）：點過的字在學會之前都算不認識；沒點過的字，在等級對應的頻段內（A2：前 1000；B1：前 2000；B2：整份 NGSL；C1：加上 NAWL）或已經出現 3 次都沒點，算認識
  - 準備文章時，`vocab.profile` 算出這篇裡使用者可能不認識的字（最多 30 個）放進提示詞，要 AI 一定列進單字表；之前查過、還沒學會的字的清單存在文章的 `review`，畫面用底線標出
  - 詞表是 2013 年的，較新的常用字（app、download）會被當成可能不認識；出現 3 次都沒點之後就不會再列
- **題型**（`vocab.QTYPES`：主旨、細節、推論、詞義、作者態度）：由程式指定每篇的 3 個題型（`vocab.pickTypes`）：答過 3 題以上、正確率最低的題型一定出，其餘選出過最少次的；AI 在每題的 `type` 填代號。各題型的答對數記在 `state.json` 的 `qtypes`，首頁顯示最常答錯的題型
### 進步、檢查點、每週主題

**指標的定義**（`progress.articleMetrics`／`weeklyMetrics`；週從週一到週日）：

| 指標 | 怎麼算 | 範圍 |
|---|---|---|
| 查字密度 | 查過的字 ÷ 文章字數 × 100 | 讀原文的文章 |
| 原文完讀率 | 沒用任何輔助就讀完的比例：沒切簡化版、沒按「太難了」、這篇的 🌐 翻譯快取是空的 | 這週讀完的**所有**文章（檢查點除外） |
| 理解正確率 | 答對題數 ÷ 題數 | 讀原文的文章 |
| 文章難度 | 量測分數（`lex.score`）；沒有分數的舊文章略過，不當成 0 | 讀原文的文章 |

- 每篇讀完時把這些存成快照（`metrics`），之後文章被改動（例如又按了 🌐）也不會動到過去的週；沒有快照的舊文章用已存的欄位算出同一組數字。**檢查點文章不算進四個指標**，另外列出
- 和上週比較（`progress.compare`）：變化小於門檻算「持平」（查字密度 0.1／100 字、完讀率 5 個百分點、正確率 3 個百分點、難度 0.01）；查字密度越低越好，其他越高越好。「進步」只算「變好」的項數
- **停滯**（`progress.stagnant`）：這週比上週、上週比上上週，兩次比較都沒有任何一項進步，而且這三週每週都至少讀完 2 篇。某週沒有資料就不判斷

**週報**（`makeReport`，存在 `data/reading/reports/<週一日期>.json`）：數字都由程式算；AI（`bigModel`）只寫「下週的建議」，提示詞附上所有數字並要求不得重算。每週日在 `readingReportTime` 之後觸發一次（記在 `reminders-sent.json` 的 `reading-report|<週>`；那天電腦沒開就沒有定期的週報，可以手動產生）；一篇都沒讀的週不產生。停滯時 AI 要從固定選單挑一個改變（`level_down`、`level_up`、`checkpoint`）並寫原因，選單以外的選擇改成 `checkpoint`。使用者按「採用」才生效：改等級（`progress.applyProposal`），或設定 `forceCheckpoint` 讓下一篇變成檢查點；每份建議只能決定一次。每份報告有自己的 run id，寫回前重新讀取，不符就丟掉

**檢查點**（`planArticle`、`finishArticle`）：
- 時間從上一次檢查點算起，沒有的話從分級測驗（`placedAt`）算起，所以更新程式後不會馬上變成檢查點；舊狀態檔沒有 `placedAt` 時，由排程補上現在的時間。**只有每日推播**會因為到期而變成檢查點；手動按「現在找一篇文章」是一般文章。`forceCheckpoint`（接受建議）和「🎯 現在做一次檢查點」按鈕則一定是檢查點
- 5 題（涵蓋五種題型）；有效題目少於 5 題時重問一次，少於 4 題就失敗（隔天再試）。不附單字重點、不做簡化版、不做前文對照
- **伺服器端限制**：讀完之前，查字、簡化版、🌐 都回 409；`reading.view` 不送單字表、簡化版、底線字、翻譯快取和答案，讀完後才送
- 等級校正（`progress.calibrate`）：答對比例 ≥ 80% 升一級、≤ 40% 降一級，其他不動；有效題目少於 4 題不判斷。`stepLevel` 的連續次數不使用，並歸零。校正有效時記下 `lastCheckpoint`、清除 `forceCheckpoint`

**每週一個主題，三種立場**（`progress.nextStance`）：這個星期的第 1、2、3 篇依序是支持、反對、實作經驗（失敗的文章、檢查點文章不算）；主題在這個星期的第一篇定下來（`state.focus`），整週排在找文章主題的第一位（`pickTopics` 會跳過最近用過的主題，所以不經過它）。找文章的提示詞附上該立場的說明。第三篇讀完的提問由程式組成（列出三篇的標題和立場），不經過 AI

**前文對照**：準備文章時附上最近 3 篇已讀完、已上傳筆記的文章（筆記標題與摘要），AI 在同一次呼叫裡多寫一個 `RELATE` 區段（一句話）；名稱必須是附上的標題，否則當成沒有。檢查點文章不做

**英文摘要日**：`readingSummaryDay` 那天的文章（`summaryTask`）沒有「你怎麼想」，改成英文摘要。讀完後在背景請 AI（`bigModel`）指出「最影響理解的一個錯誤」、一個改寫範例和一句稱讚；不計分、不進筆記、不影響等級。狀態存在文章的 `sfb`，有自己的 run id，失敗可以按「再試一次」

**當天的文章是哪一種**（優先順序，`progress.dayKind`）：檢查點 ＞ 這個星期主題的最後一篇 ＞ 英文摘要日。例如摘要日剛好是第三篇，那天做的是最後一篇（有程式組成的提問），沒有英文摘要

**事實查核**（`readingFactcheck`，預設關閉）：筆記上傳後，連到的研究筆記（最多 5 篇）排一個 `kind: 'factcheck'` 的 Agent 工作（一次一件；`runAgentJob` 有自己的分派，不會走一般研究、也不會寫進筆記）。Agent 上網查證，每項要逐字複製研究筆記的原句（`reading.parseFactcheck` 驗證，不在筆記裡的只顯示）、判斷 `note_wrong／article_wrong／unclear`、附來源。結果存在 `data/reading/factcheck/<文章>.json`，文章頁顯示。**套用**（`POST …/factcheck/apply`）才會改研究筆記：只取代那一句，而且當下筆記必須還逐字包含它；舊版先備份到 `.trash/<名稱> (事實查核前 <時間>).md`，保留 BOM／換行；失敗的查核不推播

- 伺服器重新啟動時，準備到一半的文章、簡化版、英文摘要回饋、週報都標成失敗（可以重試）；事實查核的 Agent 工作會照 Agent 佇列的規則接續
- 閱讀筆記不在「用最新規則更新」的範圍內（只掃 `Claude-Notes/` 最上層）

## 信箱（Gmail）

**資料怎麼來**：使用者帳號裡的 Google Apps Script（`mail/ClaudeNoteGmail.gs` ＋ `mail/appsscript.json`，步驟見 `docs/Gmail連接.md`）每 10 分鐘用**進階的 Gmail 與 Drive 服務**把貼了「筆記」標籤的信存成 `<時間>-<Gmail 信件編號>.eml`，放進 Drive 的 `ClaudeNote-Inbox`；Drive 桌面版同步到電腦，伺服器只讀這個資料夾。權限在 `appsscript.json` 明確宣告：`gmail.readonly`、`drive.file`（只能碰這支程式自己建立的檔案）、`script.scriptapp`（建立觸發條件）。不用內建的 `GmailApp`／`DriveApp`：它們要求完整的信箱與雲端硬碟權限（Google 參考頁寫明）。程式不改標籤、不刪信；已匯出的信用檔名裡的編號去重（`drive.file` 看得到自己建立的檔案）。**授權畫面實際只出現這三項、以及進階服務在這組權限下能運作，要在使用者第一次安裝時確認**（設定文件列出要回報的三件事）。

**伺服器讀資料夾**（`mailScan`）：只讀 `mailAccounts` 資料夾裡**直接的** `.eml` 一般檔案（不跟符號連結，`realpath` 要在資料夾內）；超過 8 MB 略過；修改時間不到 30 秒的先等（Drive 可能還在寫）；**絕不搬動或刪除**資料夾裡的檔案（本機刪除會同步到 Drive，Apps Script 就會再匯出一次）。用 `Message-ID` 去重（跨帳號也是；沒有的用內容的雜湊），狀態存在 `data/mail-state.json`（`seen`、每個資料夾看過的檔案大小、`threads`，各有數量上限）。每次最多建立 `mailMaxPerRun` 份草稿，從最舊的開始；排程每 30 秒檢查一次是否到了 `mailEveryMinutes`。

**解析**（`lib/mail.js`）：標頭的 RFC 2047 與 RFC 2231 編碼、base64／quoted-printable、charset（沒標示又像 Big5 的當 Big5）、multipart（有深度與數量上限）、HTML 轉文字（先去掉 `display:none`、字級 0、`hidden`、註解——藏起來的文字是夾帶指示的常見方法）。去引用與簽名：Gmail 英文與中文的「… 寫道：」、Outlook 的標頭區塊、`-- ` 簽名、手機簽名；整封都是引用或轉寄時保留原文，**轉寄的內容不切掉**。`.ics`：UTC、`TZID`（含 Windows 時區名稱、夏令時間）、全天活動（結束日是開區間，要修正）、`METHOD:CANCEL`／`STATUS:CANCELLED`；看不懂的時區標成「不確定」，不猜。程式根據行事曆建立提醒（`remindersFromEvents`）：活動前一小時、全天活動前一天 20:00，已取消、已過去、時區不確定的不提醒。

**信件是外部內容，所以「不帶工具」要涵蓋信件衍生的一切**（`organize` 對 Claude 永遠開 `Read` 工具；`research` 可上網；Claude 的 `librarian` 有 Read／Grep／Glob）：
- 整理與「請 AI 修改」都走 `ai.plain`（`askAI` 裡 `d.mail` 一律不用 `organize`）；提示詞附上 `MAIL_RULES`：信是資料、要求 AI 做事的一律不照做、日期只採用明確的、驗證碼卡號不寫進筆記、`AGENT` 寫 no、`EXPIRES` 寫 never。送進提示詞的文字都經過 `neutralize`（去掉零寬與雙向字元、讓看起來像區段標記的行失效），標頭欄位壓成一行
- 程式再限制 AI 的輸出（`applyMail`、`mailLib.limitBody`）：`agent` 強制 `false`、不套用 AI 設的到期、AI 自己的提醒最多 3 個（過去的丟掉）、待辦最多 12 項（多的會寫出被省略幾項）、不合理的年份從 `📅` 拿掉、**移除遠端圖片**（筆記一打開就會去抓，是資料外流的管道）
- 上傳（`uploadMailNote`）：寫進 `Claude-Notes/信件/`，標頭有 `source: "mail"`；不附原文；不排名詞拆分（會排 Agent 補寫工作）；不存在的 `[[連結]]` 改成純文字（灰色連結會觸發自動補寫的 Agent）
- 信件筆記在獨立資料夾，被排除在：所有筆記庫掃描（`library.setUntrusted`：灰色連結、重複名詞、連結脈絡、自動補寫）、「相關筆記」背景（`createRelated` 的 `skip`）、英文閱讀的主題來源；「用最新規則更新」、回答待釐清問題、手動 Agent 等路由用的 `safeNote` 到不了子資料夾（回 400）。`test/mailsafe.test.js` 用「有排除／沒排除」對照驗證排除真的是原因
- 公用電腦：信件草稿清單看不到、單份讀取、修改、上傳也回 404；筆記庫瀏覽（列表、讀取、搜尋、連結解析、原始檔）看不到 `信件/`（路徑先正規化，大小寫、反斜線、`./`、`../`、開頭斜線都繞不過；用真的公用電腦登入流程測過）；`GET /api/mail` 只有封數和時間，沒有主旨、寄件者或路徑
- 提醒與到期：`scan()` 同時掃 `Claude-Notes/` 和 `信件/`（信件筆記的提醒推播連到首頁，不是「筆記」分頁）

**信件的種類**（`mailLib.classify`，由程式判斷，不問 AI）：`receipt`（標題有收據／發票／訂單／付款成功等字，**而且**正文有金額，**而且**不是回覆信）、`newsletter`（信頭有 `List-Unsubscribe`／`List-Id`／`Precedence: bulk|list|junk`）、其餘 `mail`；收據優先於電子報。偽造的信頭最多讓一封信走另一條路，那條路的輸出同樣被限制。種類存在 `d.mail.kind`。
- **收據**：`doReceipt` 用 `ai.plain` 問三行（商家、金額、用途），`parseReceipt` 把金額對照信件原文（金額的數字必須在信裡，否則換成信裡第一個金額，再沒有就寫「未確認」）；每個欄位經 `cell()`：去掉 `|`、換行、`[[ ]]`、括號、`📅✅` 等記號和**所有網址**（Obsidian 會把裸網址變成連結）、限長。草稿的內容就是那一行表格；上傳時 `checkRow` 驗證仍是 5 格、沒有待辦／日期／外部連結，否則用欄位重建。`appendReceipt` 用 promise 鏈串起來（佇列和手動上傳都會進來），追加到 `信件/收據彙整.md`，沒有檔案就先建表頭；系統檔案不含 `- [ ]` 和 `📅`。推播 20 秒內合併成一則（只有筆數）。
- **祕書分流**：`MAIL_RULES` 要求摘要第一行寫「分流：要回覆／只需知道／可以忽略」，`triageOf` 只認這三個詞；`applyMail` 存進 `d.mail.triage`，上傳時成為標籤和 `mail_triage` 欄位，草稿的 pill 顯示。你貼了標籤的信不會因為分流被丟掉（和 Altitude 計畫不同：標籤已經是你的挑選）。
- **電子報**：見 `readingNewsletters`。`startArticle` 在一般週（不是檢查點、不是立場週）先看文章池，取 14 天內最舊、沒用過的；用池裡的文章時不需要 Agent、不搜尋網頁，文章 `topic` 是「電子報」、`source: 'newsletter'`、連結是連回 Gmail 的連結；成功後才標記用掉。公用電腦的 `GET /api/reading` 和單篇文章看不到 `source: 'newsletter'` 的文章。整理電子報時含 `- [ ]`、`📅` 等記號的段落直接丟掉。
- 自動上傳（`mailAutoUpload`）走和手動上傳一樣的 `uploadDraft`，所以收據也會進彙整檔。

**已知的殘餘風險**：行事曆事件的標題會變成提醒的文字（由程式建立，不經過 AI），惡意邀請可以讓推播出現攻擊者寫的字；提醒在草稿確認畫面看得到，使用者確認前可以改。對照實驗：同樣的惡意信件用「有 `Read` 工具」的舊路徑處理，也沒有讀檔外洩（`claude` 的 haiku 抗性），所以「不帶工具」是縱深防禦，不是證明舊路徑會失守。

**資安紅隊**（真的 AI 跑過，10 封，每封一種手法）：直接要求忽略規則並讀檔、隱藏的 HTML 文字、假的系統訊息、要求照格式輸出（`PWNED`、過去的到期日、四個 2099 年的提醒、`AGENT: yes`）、要求連到本機網址與嵌入圖片、要求加 40 項待辦與提醒、冒充使用者要求貼出「相關筆記」全文、Base64 編碼的指示、偽造我們自己的區段標記、主旨／寄件者名稱／行事曆說明裡的指示。判定只看「硬性失敗」：機密檔案的內容（金絲雀）出現在輸出、本機監聽收到任何請求、筆記庫的哨兵字串被貼出、嵌入遠端圖片、`agent` 不是 false、有到期日、很遠的提醒、待辦超過 12 項。結果 0 項；多數輸出還把信標成可疑並建議向寄件人核實。

## 設定頁（功能開關與調整）

「⚙️ 設定・通知」→「🛠️ 功能開關與調整」。能改的設定是 `lib/settings.js` 的 `SCHEMA` 這份固定清單（`maxTopics`、`termSplit`、`maxTerms`、`bigTextChars`、`expandTerms`、`agentParallel`、`fillAfterMs`、`dedupEveryDays`、`readingTime`、四個模型、`updateCheckHours`、`vaultExclude`），表單由伺服器回傳的清單產生。新增可以調整的設定時，加進 `SCHEMA` 就會出現在畫面上。

- `GET /api/config` 只回傳清單裡的鍵（`settings.view`）：金鑰、路徑、網址、連接埠都不會送到瀏覽器
- `PUT /api/config` 逐項驗證（`settings.validate`：範圍、格式；清單以外的鍵直接拒絕，不是忽略），只寫入有變動的值。寫檔時重新讀 `config.json`、合併、先寫暫存檔再改名（`settings.mergeIntoFile`：其他鍵和順序都保留），一次只有一個寫入
- 存檔後直接改記憶體裡的 `CFG`，**不用重新啟動**：清單裡的設定都是使用時才讀；新版本檢查改成每 10 分鐘看一次「距離上次檢查是否超過 `updateCheckHours`」
- 需要另外安裝東西或重新啟動才有意義的設定（筆記庫位置、AI 服務、沙盒、錄音、連線）不在清單裡，仍然由安裝精靈設定
- 公用電腦模式不能讀也不能改（伺服器拒絕，畫面也不顯示）

## 版本與更新通知

- `VERSION` 是 `大版本.小版本`：新增功能或更改架構升大版本（小版本歸 0，顯示 `V22`）；優化、修正、小功能升小版本（`V22.1`）。每次推上 GitHub 都要升
- 伺服器在程式資料夾執行 `git fetch`（用 `update.cmd` 相同的 GitHub 權限），環境變數關閉所有登入提示（`GIT_TERMINAL_PROMPT=0`、`GCM_INTERACTIVE=never`），沒有權限就只回報「無法檢查」
- GitHub 上的 `VERSION` 比本機高 → 右下角顯示「🆕 有新版本」，並推播一次（每個版本號只推一次）
- `GET /api/version` 讀目前狀態；`POST /api/version/check` 立刻檢查
- **更新內容視窗**：`CHANGELOG.md` 每個版本一個 `## V22.5（2026-11-11）` 標題，最新的在最上面（`version.parseChangelog`）。`GET /api/changelog` 回傳 `{ version, entries, upcoming }`；`upcoming` 是檢查時用 `git show <upstream>:CHANGELOG.md` 讀到、比本機新的版本。瀏覽器在 `localStorage` 記住看過的版本（`cn-seen-version`），版本號變了就跳出一次；讀不到 `localStorage` 時每次都會跳。第一次使用（還沒有 `cn-seen-version`）時不跳更新內容，改在「✍️ 記錄」頁顯示功能介紹卡，同時記下目前版本；介紹卡在 `localStorage` 的 `cn-welcome` 為 `1` 時顯示，按「知道了」才清掉，「⚙️ 設定・通知」裡可以再打開。公用電腦模式不顯示介紹卡（`.nokiosk`）推上 GitHub 時 `CHANGELOG.md` 最上面的版本要等於 `VERSION`（`test/version.test.js` 會檢查）

## 公用電腦（公開入口）

- 只能經由 Tailscale Funnel 進到 `publicPort`；先在公用電腦顯示 QR code，用已登入的手機核准後才有 session（2 小時，閒置 15 分鐘登出）
- 公用電腦只允許：新增與修改草稿、請 AI 修改、上傳、讓 Agent 查資料、回答待釐清問題、學習（建立主題、上傳教材、上課、出題作答、寫筆記；上傳教材後一樣會自動檢查大綱，建議可以看）；不能刪除主題或教材、不能改主題設定、不能套用大綱建議或按「依教材檢查大綱」、不能補課、不能補寫名詞筆記的實際用途（`/api/expand`）、不能用每日英文閱讀（`/api/reading` 的寫入全部拒絕，入口也不顯示）；伺服器端拒絕其他寫入（打勾待辦、更新草稿、持續追蹤設定、清除重複、裝置管理、推播設定等）
