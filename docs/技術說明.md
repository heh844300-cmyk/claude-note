# 技術說明

## 架構

```
 手機 PWA ──Tailscale Serve (https)──┐
 公用電腦 ──Tailscale Funnel (https)─┤──► 127.0.0.1:8788 公開入口（QR 登入、公用電腦權限限制）──┐
 本機瀏覽器 ─────────────────────────┴──► 127.0.0.1:8787 ◄──────────────────────────────────────┘
                                            mobile/server.js（Node 20+，零依賴）
                                            ├─ 草稿工作佇列（整理／修改／更新，一次一件）
                                            ├─ Agent 工作佇列（研究／灰色連結補寫／名詞拆分，一次一件）
                                            ├─ 排程（每 30 秒）：提醒推播、到期移到 .trash、灰色連結、例會報告
                                            └─ 排程（每小時／每 6 小時）：重複名詞掃描、新版本檢查
                                                 │
                     ┌───────────────┬──────────┴──────────┬────────────────────┐
                     ▼               ▼                     ▼                    ▼
               AI（lib/ai.js）   網路（Agent）       Obsidian 筆記庫         Web Push
          Claude Code／Codex／   內建搜尋或          Claude-Notes/、研究/   （手機、電腦）
          OpenAI 相容 API        Tavily／Brave       .trash（到期、備份）
```

連接埠是預設值：`port` 預設 8787；公開入口 `publicPort` 預設關閉（0），由安裝精靈設定。

### 模組（`mobile/lib/`）

| 模組 | 負責 |
|---|---|
| `ai.js` | AI 介面：Claude Code CLI、Codex CLI 或 OpenAI 相容 API；角色有 organize（整理）、research（研究員）、librarian（圖書管理員）、plain（不用工具的單次問答） |
| `webtools.js` | openai 模式 Agent 的網路搜尋（Tavily／Brave）與安全網頁讀取 |
| `sandbox-mcp.js` | Agent 沙盒的 MCP 伺服器（`sandbox_run` 工具） |
| `vault.js` | 讀取整個筆記庫（排除點開頭的資料夾與 `vaultExclude`）：清單、搜尋、`[[名稱]]` 解析 |
| `related.js` | 找出和輸入相關的既有筆記（英文單字＋中文雙字詞、IDF 加權，筆記名稱出現在文中時大幅加分），附在 AI 提示裡 |
| `split.js` | 一次輸入拆成多篇、總覽、名詞解釋拆分 |
| `library.js` | 研究結果分篇（link／append／new／inline）、灰色連結、筆記庫掃描 |
| `answers.js` | 使用者對「待釐清問題」的 💬 回答；已釐清的問題移到「已釐清」 |
| `refresh.js` | 「用最新規則更新」：只重寫正文區，打勾、回答、已釐清等使用者動過的內容由程式保留 |
| `dedup.js` | 重複名詞筆記與灰色連結的偵測、合併、改連結 |
| `tasks.js` | 解析與切換待辦（`📅` 到期日、`✅` 完成日） |
| `series.js` | 持續追蹤：主筆記設定、每日紀錄、「每日紀錄」索引、例會報告 |
| `htmltext.js` | HTML 教材轉文字：依 BOM、`<meta charset>` 判斷編碼（沒宣告時自動辨識 Big5），去掉 script／style／Word 標記，標題、清單、表格轉成 Markdown |
| `learn.js` | 學習：大綱解析、讀書計畫、出題解析、批改、錯題本與大綱筆記的產生、教材段落挑選、各種提示 |
| `version.js` | 讀 `VERSION`、`git fetch` 比對 GitHub 上的版本；解析 `CHANGELOG.md` 給「更新內容」視窗 |
| `auth.js` | 公開入口的 QR code 登入與裝置 session |
| `push.js` | Web Push（RFC 8291／8292，VAPID） |
| `qr.js` | QR code 產生器 |

### 一篇筆記的資料流

1. **新增**：`POST /api/drafts`（文字、照片、錄音）→ 草稿存在 `mobile/data/drafts/<id>/`
2. **整理**：`prompt.md` ＋ 時間與提醒規則 ＋ 相關既有筆記（`related.js`）＋ 持續追蹤的主筆記（`series.js`）→ AI → 解析標頭（`TITLE`、`TAGS`、`EXPIRES`、`REMIND`、`AGENT`、`SERIES`）與正文
3. **確認**：使用者修改或請 AI 重改 → 上傳到 `Claude-Notes/YYYY-MM-DD 標題.md`（持續追蹤的話寫進當天的每日紀錄）
4. **上傳後的背景工作**：名詞解釋拆分 → 需要時 Agent 研究（研究員查資料 → 圖書管理員決定放哪裡 → 寫回「Agent 研究結果」、打勾、移到「已釐清」）
5. **排程**：提醒時間到推播；到期移到 `.trash`

### 筆記的區段

伺服器只改自己負責的區段，其他內容照原樣保留：

| 區段 | 誰寫 | 「用最新規則更新」時 |
|---|---|---|
| frontmatter、`# 標題`、`> 🧩`／`> 📌` 連回連結 | 上傳時 | 不動 |
| 正文（摘要、重點、思路、待辦、待釐清問題、已釐清、相關概念） | 整理 AI、使用者 | 重寫；打勾、📅、💬 回答、已釐清由程式補回 |
| `## 每日紀錄` | 持續追蹤 | 不動 |
| `## Agent 研究結果` | Agent | 不動（下次 Agent 執行時整段取代） |
| `## 附件照片`、`Original notes`、錄音逐字稿 | 上傳時 | 不動 |

| 檔案 | 用途 |
|---|---|
| `setup.cmd`／`setup/setup.ps1` | 安裝精靈，寫 `mobile/config.json` |
| `update.cmd` | `git pull` 後重新啟動 |
| `VERSION` | 版本號 `大版本.小版本`（右下角顯示、更新通知用） |
| `mobile/config.json` | 這台電腦的設定（不進版控） |

## 設定（mobile/config.json）

| 鍵 | 說明 |
|---|---|
| `vault` | Obsidian 筆記庫資料夾（必填，沒填伺服器不會啟動） |
| `provider` | `claude`、`codex` 或 `openai` |
| `codex` | Codex CLI 的 codex.js 路徑（provider 為 codex；模型留空＝用方案預設模型） |
| `claude` | claude.exe 路徑（provider 為 claude） |
| `apiBaseUrl`、`apiKey` | OpenAI 相容服務的網址與金鑰 |
| `smallModel`、`bigModel`、`agentModel`、`librarianModel` | 各角色用的模型 |
| `vision` | 整理用的模型能不能讀圖片 |
| `search` | `{ "provider": "tavily" 或 "brave", "apiKey": "…" }`，openai 模式的 Agent 需要 |
| `publicUrl` | 手機用的 Tailscale 網址（推播連結） |
| `publicPort`、`funnelUrl` | 公開入口（QR 登入），0 為關閉 |
| `audio`、`ffmpeg`、`whisper`、`whisperModel` | 錄音轉文字（進階，需自行安裝 ffmpeg 與 whisper.cpp） |
| `sandbox`、`sandboxName`、`sandboxDir` | Agent 沙盒（Claude 與 Codex）：是否啟用、WSL 發行版名稱、快照與虛擬磁碟的資料夾（預設 `sandbox/`） |
| `vaultExclude` | 「筆記庫」分頁不顯示的資料夾（點開頭的資料夾一律不顯示） |
| `fillAfterMs` | 灰色連結空白多久後自動補（預設 60000，0 為關閉） |
| `agentMaxRounds`、`agentMaxSearches` | openai 模式 Agent 每次工作的工具呼叫輪數、搜尋次數上限 |
| `termSplit` | 上傳後把名詞解釋拆成研究筆記（預設 true） |
| `maxTopics` | 一次輸入最多拆成幾篇主題筆記（預設 6，可設 2～20）；AI 拆得比這個多時，多出來的主題併進最後一篇，不會丟掉 |
| `maxTerms` | 每篇筆記最多拆出幾個名詞解釋到 `研究/`（預設 5，可設 1～20）；學習筆記也適用 |
| `dedupEveryDays` | 每幾天自動掃描一次重複名詞（預設 7，0 為只用按鈕） |
| `updateCheckHours` | 每幾小時到 GitHub 檢查新版本（預設 6，0 為關閉） |
| `bigTextChars` | 輸入超過這個字數（或有照片、錄音）時改用 `bigModel` 整理（預設 1500） |
| `lateReminderMs` | 電腦關機時錯過的提醒，開機後多久內還會補送（預設 6 小時） |
| `claudeTimeoutMs`、`agentTimeoutMs`、`librarianTimeoutMs` | 整理、Agent、圖書管理員（含報告、重複掃描）的逾時 |

## AI 角色與安全設計

| 角色 | 能做的事 | 做不到的事 |
|---|---|---|
| 整理 | 讀草稿文字與照片 | 上網、讀其他檔案 |
| 研究員（Agent） | 網路搜尋、讀公開網頁 | 讀筆記庫、連到本機或內部網路 |
| 圖書管理員 | 看筆記庫（Claude：唯讀工具；其他 AI：伺服器挑出的相關筆記摘錄） | 上網；它只輸出「放哪裡」的決定，寫進檔案的文字都來自研究員 |

- openai 模式的網頁讀取（`fetch_url`）在這台電腦上執行，所以會拒絕所有本機、私有網段、Tailscale 位址，連線時與每次轉址都會重新檢查（`test/webtools.test.js`）
- Agent 的研究結果只會新增或追加到筆記，不會覆蓋既有內容；會改寫既有筆記的只有使用者確認過的動作（上傳更新草稿、合併重複名詞），而且舊版先備份或移到 `.trash`。伺服器不會寫到 `.obsidian`

## Codex（ChatGPT 訂閱）的權限鎖定

Codex 本身是會執行指令的 Agent，所以每次呼叫都會：

- `-s read-only`、`--ignore-user-config`（不載入使用者的 MCP 等設定）、`--ephemeral`
- 關閉 `shell_tool`、`unified_exec`、`view_image`、`apps`、`plugins`、`browser_use`、`browser_use_external`、`computer_use`、`in_app_browser`、`hooks`
- 在 `%TEMP%\claude-note-codex-empty` 執行：每次都清空，而且不在任何 git 專案裡，Codex 不會讀到專案的 AGENTS.md 或 .codex 設定；照片用 `--image` 直接附上
- 關閉的功能名稱如果在新版 Codex 不存在，Codex 會直接報錯停止（`Unknown feature flag`），不會在沒鎖定的狀態下執行
- 只有研究員加 `--search`（OpenAI 伺服器端的網路搜尋，連不到這台電腦）；管理員跟 OpenAI 模式一樣只拿到伺服器挑出的筆記摘錄

在 codex-cli 0.160.0 實測：要求它讀取工作資料夾外的檔案、執行指令、用 JavaScript（code mode）讀檔或連到本機的陷阱伺服器，全部失敗，陷阱伺服器沒有收到任何連線；網路搜尋正常。**Codex 大改版後請重新做一次這個測試**（`test/ai-codex.test.js` 只檢查參數，不檢查 Codex 本身的行為）。

## 一次輸入拆成多篇、名詞解釋拆分

- 整理時，AI 判斷輸入是否包含多個**彼此不相關**的主題（最多 `maxTopics` 個，預設 6）。是的話，原草稿變成「總覽」（保留照片、原始輸入、逐字稿），每個主題另開一份草稿，各自有提醒、到期、Agent。單一主題完全照舊；AI 輸出格式不對時，當成一篇處理；拆出的主題超過上限時，多的併進最後一篇（標題降一級），內容都不會遺失。學習功能的筆記一律整理成一篇，不會拆
- 總覽不能單獨上傳：等這一組的主題都上傳（或刪除）後自動寫入，連結用各篇實際的檔名，並在各篇開頭加上連回總覽的連結；主題全部刪除時總覽也跟著取消
- 修改單一主題時，會拿總覽裡的原始素材，只輸出那一篇
- 每篇筆記上傳後（總覽除外），背景工作找出「說明某個名詞是什麼」的段落：AI 只指出段落，必須逐字出現在筆記裡、不在「相關概念」裡，伺服器才把它換成「摘要（詳見 → [[研究/名詞]]）」；放哪裡由管理員判斷（新開、補充既有、或已涵蓋只放連結）。被換掉的原文保留在同一篇最後的「拆出前的原文」摺疊區塊。不看字數，由 AI 判斷是不是名詞解釋。關閉：`config.json` 的 `"termSplit": false`

## Agent 沙盒

安裝精靈第 7 步（`setup/sandbox-setup.js`）建立一個隔離的 WSL 發行版（Ubuntu 24.04）：

- 用沒有管理員權限的 `agent` 使用者（uid 2001）執行；`sudo`／`su` 不能用、看不到 Windows 磁碟、不能執行 Windows 程式
- 防火牆只允許連公開網路：本機、WSL 閘道、區網、Tailscale 都擋（`sandbox/ensure-sandbox.sh`，每個指令前都會重新套用）
- 建立完會跑 `sandbox/isolation-test.sh`（用這台電腦實際的 Tailscale 位址與區網閘道），**有任何一項沒擋住就不啟用**；`/mnt/wsl` 可寫入是已知限制（整個 WSL 共用，遮掉會讓 WSL 壞掉）
- 每個 Agent 工作第一次用沙盒時，從 `clean.tar` 快照還原成乾淨狀態
- 只會 `--terminate` 沙盒自己，絕不 `wsl --shutdown`；WSL 已有同名、但不是這個程式建立的發行版時，會停止而不動它
- Claude Code 透過 `--mcp-config` 使用；Codex 透過 `-c mcp_servers.sandbox...`，**只預先核准 `sandbox_run` 這一個工具**（codex-cli 0.160.0 實測可用；如果之後的版本不認這個設定，呼叫會被拒絕，不會變成沒有限制）
- 實測（codex-cli 0.160.0）：讓 Codex 用沙盒連本機、閘道、區網 IP、Tailscale IP、讀 C 槽、提權，全部失敗，架在這台電腦所有網路介面上的陷阱伺服器沒有收到任何連線；實際安裝並執行 cowsay 成功
- 解除安裝精靈會先移除本程式建立的沙盒，才刪除程式資料夾

## 研究結果分篇

- `link`：已有筆記涵蓋 → 原筆記只放摘要＋連結
- `append`：既有筆記的細節 → 補在那篇最後（標示「🔎 Agent 補充」，原文不動）
- `new`：獨立概念 → `Claude-Notes/研究/` 開新筆記；名稱優先用現有的灰色連結
- `inline`：留在原筆記
- 重跑同一篇不會重複補充；有到期日的筆記不會被補充（改開新筆記）

## 灰色連結自動補

伺服器每 30 秒掃描筆記庫：內容空白、檔名跟某篇筆記的 `[[連結]]` 相同、而且空白超過 1 分鐘的筆記，會交給 Agent 寫成完整筆記，移到 `Claude-Notes/研究/`。1 分鐘內打字就不會被碰。手動指定：`POST /api/fill {"name":"名詞"}`。

## 參考既有筆記

整理、修改、更新、Agent 研究、灰色連結補寫之前，`related.js` 會從筆記庫挑出最相關的幾篇（摘要＋章節＋開頭，每篇約 1000 字），連同 `研究/` 裡已有的名詞清單附在提示裡。

- 只透過 `vault.js` 讀取，所以 `vaultExclude` 和點開頭的資料夾不會送給 AI
- 持續追蹤的每日紀錄不列入（幾十篇相似的進度會擠掉其他筆記），它們由持續追蹤另外提供
- 使用者在 💬 回答裡寫的 `[[筆記]]`，內容會整篇附給 Agent（Agent 本身讀不到筆記庫）

## 回答待釐清問題、已釐清

- 回答寫成問題底下的 `  - 💬 我的回答：…` 子項目；儲存時比對行號與原文，筆記剛被改過就拒絕（避免寫錯行）
- Agent 輸出 `RESOLVED: <問題原文> | <結論>`：使用者回答過、或查到明確事實的問題，從「待釐清問題」移到 `## 已釐清`（問題、回答、結論）；要使用者拍板的問題不算

## 用最新規則更新

- 一篇或全部筆記先產生「更新草稿」，確認後才上傳；一律用 `bigModel`
- 上傳時只取代正文區（見[筆記的區段](#筆記的區段)），舊版先備份到 `.trash/<名稱> (更新前 <時間>).md`
- 草稿建立後筆記被改過（忽略打勾與回答）就拒絕上傳；之後的打勾、回答在上傳時合併
- 不更新：`研究/` 名詞筆記、總覽、使用者自己寫的筆記、每日紀錄

## 清除重複名詞

- 掃描範圍：`研究/` 筆記（名稱＋摘要）和可見筆記裡的灰色連結；系統先用名稱比對（去掉「方法、框架、模型…」等字尾）當提示，再由 AI 判斷是不是**同一個概念**（一部分、一種技巧、相關但不同都不算）
- 每一組都要使用者按「合併」才動：重複筆記的內容併進保留的那篇、加進 `aliases:`、全筆記庫的 `[[重複]]` 改成 `[[保留|原本顯示的字]]`、重複的那篇移到 `.trash`
- 按「不是重複」的組合之後不會再出現；灰色連結補寫時，AI 判斷是同一個概念的話直接改連過去，不建新筆記

## 待辦

- 掃描整個可見筆記庫的 `- [ ]`／`- [x]`；`📅 YYYY-MM-DD` 是到期日、`✅ YYYY-MM-DD` 是完成日（和 Obsidian Tasks 外掛相同格式）
- 打勾時比對行號與原文，保留檔案原本的 BOM 與換行

## 持續追蹤

主筆記的 frontmatter（都是單一值，簡單的 YAML 解析器就讀得到）：

```yaml
series: true
series_name: "例會進度"   # 每日紀錄的檔名：YYYY-MM-DD 例會進度.md
series_days: "1-5"        # 週一 = 1 … 週日 = 7，也可以寫 "1,3,5"
series_time: "12:10"      # 留空 = 不自動整理報告
series_start: 2026-11-16  # 這天之前不整理報告
```

- **整理**：使用者選「接續到」，或交給 AI 判斷（提示裡附上最多 4 篇主筆記，每篇含最近兩次紀錄），AI 在標頭輸出 `SERIES: <主筆記標題>` 或 `SERIES: none`
- **每日紀錄**：frontmatter 有 `series_of: "<主筆記檔名>"`，開頭 `> 📌 接續 [[主筆記]]`；不會到期、沒有自己的提醒；日期取「寫下的那天」；同一天第二次上傳接在後面的 `## 補充（HH:mm）`
- **索引**：主筆記的 `## 每日紀錄`，最新的在最上面（在正文區之外，更新、名詞拆分、Agent 都不會動它）
- **報告**：例會前 30 分鐘（`series_lead`）由排程觸發，不走 Agent 佇列；取上一次例會日之後的紀錄，用 `smallModel` 寫成 `## 例會報告`，放在當天紀錄最上面並推播。同一場例會只觸發一次（記在 `data/reminders-sent.json`，重開機也不會重複）；AI 失敗時改放直接從筆記整理的紀錄與未完成待辦

## 學習

每個主題一個資料夾 `Claude-Notes/學習/<主題>/`：

| 檔案 | 內容 |
|---|---|
| `.learn/topic.json` | 主題的真實資料：章節與進度、教材清單、測驗紀錄、錯題、考試日期、推播時間（點開頭的資料夾 Obsidian 不顯示） |
| `.learn/lesson-<章>.json` | 該章的教學內容、追問紀錄、上課筆記 |
| `.learn/quiz-<id>.json` | 題目、**答案與評分要點**、作答、批改結果 |
| `.learn/text/<教材>.txt` | 照片、HTML 教材轉出來的文字（只轉一次） |
| `大綱.md`、`錯題本.md` | 由 `topic.json` 產生，每次變動都重寫（不要手動改） |
| `第N章 <標題>.md`、`測驗 ….md` | 使用者的筆記，經過一般的「整理 → 草稿 → 上傳」流程；同名時接在後面 |
| `教材/` | 原始教材 |

- **AI 呼叫**有自己的佇列（不排在 Agent 後面），一次一件；前端輪詢狀態。伺服器重新啟動時，做到一半的工作標成失敗讓使用者重來
- **大綱**：有教材時，文字與照片轉出的文字用 `pickPassages`（和 `related.js` 一樣的雙字詞比對）挑出最多 2 萬字，PDF 交給 Claude 用 Read 工具整份讀；沒有教材時用研究員角色上網查證（沒有搜尋服務就只用 AI 知識）
- **上課**：研究員角色（AI 知識＋網路查證）＋相關既有筆記；追問用不帶工具的單次問答，附上這一章的內容和最近 6 則問答
- **出題**：輸出 JSON（每題一個物件，壞掉的部分略過）；範圍內章節的教材段落、考古題段落（仿照風格）、待複習錯題（只練錯題）附在提示裡。**答案、評分要點、解析只存在伺服器**，交卷前送到瀏覽器的只有題目和選項
- **使用者的要求**：主題的 `rules`（教學要求）放進大綱、上課、追問、出題、批改的提示；每份測驗的 `settings.rules`（出題要求）放進出題與批改的提示，最後一次用的會存成 `quizRules` 下次預先帶入。要求放在輸出格式之前，並註明「和格式衝突時以格式為準」
- **動態難度**：等級與計數器由程式保存，AI 只負責判斷對錯、照指定等級出題。規則（`learn.stepLevel`）：連對 2 題升一級、連錯 2 題降一級（1～5 級，起始 2 級）、答錯第 1 次維持等級並要求再試、用了提示才答對只清掉連錯不算連對。每章等級存在 `topic.json` 的 `levels`，每份測驗批改後依作答順序更新；應考出題選「自動」或章節小測驗時，提示裡寫出每章的等級與該級的出題標準。小問題的狀態存在 `lesson-<章>.json` 的 `adapt`（從該章等級開始）：提示裡直接給 AI「答對時／答錯時」該怎麼做的分支（不用 AI 自己算），AI 回答的第一行寫 `JUDGE: correct|wrong|none`，伺服器讀出後藏起來並更新等級
- **5 級難度**（`learn.LEVELS`，每級分別寫了上課小問題 `chat` 與測驗出題 `quiz` 的標準；舊資料的 easy／medium／hard 對應到 2／3／4 級）：

  | 等級 | 名稱 | 測驗出題標準（摘要） |
  |---|---|---|
  | 1 | 基礎建立 | 最基本的定義與觀念辨認；選擇題可以只有兩個合理選項（沒有是非題型，用二選一代替） |
  | 2 | 標準入門 | 基礎專有名詞與定義、單一概念 |
  | 3 | 概念應用 | 情境應用、小型計算或推演 |
  | 4 | 進階變形 | 邊界條件、常見陷阱、多概念綜合、找錯題 |
  | 5 | 大師挑戰 | 底層原理、方案取捨、設計與優化 |

  出題設定的 `difficulty` 是 `auto` 或 `1`～`5`；章節小測驗固定用 `auto`。這個版本之前做過的測驗不回溯計算，章節沒有紀錄時從 2 級開始
- **HTML 教材**（`htmltext.js`）：上傳時轉成文字存到 `.learn/text/`，之後和文字檔一樣用 `pickPassages` 挑段落；轉出來幾乎沒有文字的（例如整頁都是圖片）直接拒絕
- **作答提示**：每題最多 2 個，交給 AI 時附上答案（只給 AI 參考）並要求不能說出、描述或用排除法暗示答案；回來的提示若包含正確選項的文字或字母、或任一可接受的填空答案，就重新產生（最多 2 次），仍不行就改用章節重點當提示。提示存在測驗檔裡，結果畫面標出用了幾個
- **追問的小問題**：學生問新問題時，回答最後出一個「🤔 小問題」；學生在發問框回答時，AI 先指出哪裡對、哪裡是盲點再補充，**不再接著出新的小問題**（避免一直追問下去）。唯一的例外是第 1 次答錯：請學生「🤔 再試一次」同一題；同一題第 2 次答錯就直接說明答案。想多練時按「🎯 再來一題」（`POST …/lesson/:n/ask` 帶 `{ more: true }`）：只照目前等級出一個新的小問題，不判斷對錯、不改連對連錯的計數
- **發問與回答共用一個輸入框**：送出時帶 `mode`：`ask`（新問題，一定不判斷對錯）、`answer`（回答目前等著的小問題，一定判斷對錯；提示裡附上那一題）、`auto`（預設，AI 自己判斷，提示裡也附上等著的小問題）。等著的小問題由 `learn.pendingQuestion` 從最後一則回答的「🤔 小問題／再試一次」取出；沒有的話不能選「回答小問題」（伺服器也會拒絕）
- **問答串**：每則紀錄存 `kind`（`ask`／`answer`／`more`），`learn.threadsOf` 把新問題當成一串的開頭，小問題的回答和「再來一題」接在它底下（舊紀錄沒有 `kind`：有判斷對錯的、或「再來一題」算回覆）。`GET …/lesson/:n` 回傳 `threads` 和 `pending`。上課頁每一串是一個 `<details>`，標題列出回覆數和 ✅❌；最新的一串預設展開、舊的收起，使用者手動切換的狀態記在記憶體裡，畫面輪詢重畫時保留
- **批改**：選擇題比對選項；填空每個空格可接受多種寫法（忽略全半形、大小寫、空白與標點），依答對的空格給分；開放題所有題目一次交給 AI，分數限制在 0～滿分，沒作答直接 0 分。低於滿分六成記進錯題本；「只練錯題」的題目帶著錯題編號，答對就把那題移到「已熟練」
- **讀書計畫**：從今天到考試前一天，最後約 20%（最多 3 天）留給模擬考與錯題，未完成的章節平均分到其他天、前面的天先排；每次都從「還沒完成的章節」重算，所以落後會自動往後排。每天 `planTime` 後 3 小時內推播一次（記在 `data/reminders-sent.json`）
- **PDF**：只有 provider 為 `claude` 時可以上傳。實測 Claude Code 的 Read 工具不指定頁數時可以整份讀（含掃描檔）；指定頁數需要另外安裝 poppler，所以不使用
- **上傳前審查**：學習筆記的草稿整理好（或請 AI 修改完）後，自動跑一次審查（`learn.reviewPrompt`）：對照草稿的原始內容（這一章的教學內容、上課問答、測驗結果、使用者筆記）、`pickPassages` 挑出的教材段落，有搜尋服務時用研究員角色上網查證，沒有就用不帶工具的單次問答。PDF 教材不會列入審查（畫面會註明）。AI 只挑事實與觀念錯誤（不挑文筆、格式、心得），最多 10 條，每條 `LEVEL`（錯誤／不精確／待查）、`QUOTE`（逐字原文）、`PROBLEM`、`FIX`（可以直接取代原文的寫法）、`SOURCE`。`learn.parseReview` 在正文裡找原文（忽略多餘空白），找不到的只顯示、不能自動套用；`learn.applyFixes` 每條只取代一次
  - 結果存在草稿資料夾的 `review.json`（不寫進 `draft.json`，避免和使用者存檔互相覆蓋），有自己的佇列（不卡上課，也不排在 Agent 後面）。每次審查有自己的 id：重新審查或請 AI 修改後開始的新審查，會讓還在跑的舊審查結果直接丟掉；草稿已經上傳或刪除時也不寫回（不會留下空的草稿資料夾）。伺服器重新啟動時，中斷的審查標成失敗
  - `POST /api/drafts/:id/review`（重新審查，可附目前的編輯內容）、`POST /api/drafts/:id/review/apply`（`{ ids, action: apply | ignore | reopen }`，附目前的編輯內容，套用後回傳新的草稿）。公用電腦也可以用。草稿清單顯示「🔍 審查中」「⚠️ N 個問題」「✅ 已審查」；N 只算還沒處理、原文還在正文裡的「錯誤」和「不精確」，上傳前的確認視窗也用同一個數字提醒
- 系統產生的檔案不用 `- [ ]` 和 `📅`，避免出現在「待辦」分頁和 Tasks 外掛

## 版本與更新通知

- `VERSION` 是 `大版本.小版本`：新增功能或更改架構升大版本（小版本歸 0，顯示 `V22`）；優化、修正、小功能升小版本（`V22.1`）。每次推上 GitHub 都要升
- 伺服器在程式資料夾執行 `git fetch`（用 `update.cmd` 相同的 GitHub 權限），環境變數關閉所有登入提示（`GIT_TERMINAL_PROMPT=0`、`GCM_INTERACTIVE=never`），沒有權限就只回報「無法檢查」
- GitHub 上的 `VERSION` 比本機高 → 右下角顯示「🆕 有新版本」，並推播一次（每個版本號只推一次）
- `GET /api/version` 讀目前狀態；`POST /api/version/check` 立刻檢查
- **更新內容視窗**：`CHANGELOG.md` 每個版本一個 `## V22.5（2026-11-11）` 標題，最新的在最上面（`version.parseChangelog`）。`GET /api/changelog` 回傳 `{ version, entries, upcoming }`；`upcoming` 是檢查時用 `git show <upstream>:CHANGELOG.md` 讀到、比本機新的版本。瀏覽器在 `localStorage` 記住看過的版本（`cn-seen-version`），版本號變了就跳出一次；讀不到 `localStorage` 時每次都會跳。推上 GitHub 時 `CHANGELOG.md` 最上面的版本要等於 `VERSION`（`test/version.test.js` 會檢查）

## 公用電腦（公開入口）

- 只能經由 Tailscale Funnel 進到 `publicPort`；先在公用電腦顯示 QR code，用已登入的手機核准後才有 session（2 小時，閒置 15 分鐘登出）
- 公用電腦只允許：新增與修改草稿、請 AI 修改、上傳、讓 Agent 查資料、回答待釐清問題、學習（建立主題、上傳教材、上課、出題作答、寫筆記）；不能刪除主題或教材、不能改主題設定；伺服器端拒絕其他寫入（打勾待辦、更新草稿、持續追蹤設定、清除重複、裝置管理、推播設定等）

$env:CN_CONFIG = "C:\path\test-config.json"
